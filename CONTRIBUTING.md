# Development and commit conventions

- Work on a feature branch, then open a pull request against `main`.
- Make a focused commit when a cohesive change is complete: schema, authentication, checkout, UI, tests or documentation.
- Use descriptive messages and include the tests actually run in your pull request.
- Preserve authentic author and committer dates. Do not backdate work or manufacture a historical development trail.
- Treat AI-assisted code like any other contributed code: verify it, test it and clearly describe your personal decisions and review work.
- Never commit `.env`, live payment keys, customer data, seller identity documents or database dumps.
- Update README's **unverified** and **not implemented** lists as features are genuinely tested and released.
